## SECURITY VULNERABILITIES

### BE-SEC-001 — 🔴 CRITICAL: No Authentication or Authorization on Any Endpoint

**Files:** `backend/app/routers/cms.py`, `backend/app/routers/templates.py`

**Location:** All route handlers in both routers

**Description:**  
Every CMS endpoint (create, read, update, delete for pages and templates) is fully public. There are no authentication guards, no token validation, no role-based access control on any route. Anyone can delete pages, create templates, or modify published content.

**Affected endpoints:**
- `GET /api/v1/cms/pages` — lists all pages (cms.py L28)
- `POST /api/v1/cms/pages` — creates pages (cms.py L42-43)
- `PUT /api/v1/cms/pages/{slug}` — updates pages (cms.py L55-57)
- `DELETE /api/v1/cms/pages/{slug}` — deletes pages (cms.py L70)
- `GET/POST/PUT/DELETE /api/v1/templates/*` — all template CRUD (templates.py L36-80)

**Code example (cms.py L28-29):**
```python
@router.get("/pages", response_model=list[PageListItem])
async def cms_list_pages(db: Any = Depends(get_db)) -> list[PageListItem]:
    return await list_pages(db)
    # No Depends(get_current_user), no auth middleware, no API key
```

**Impact:** Complete data breach. Attacker can enumerate, modify, or wipe all CMS content.

### BE-SEC-002 — 🔴 CRITICAL: HTML Sanitization Completely Broken (Regex Double-Escaping)

**File:** `backend/app/utils/validators.py`

**Location:** Lines 5-21, every regex pattern

**Description:**  
All regex patterns in `sanitize_html()` use `\\s`, `\\w`, `\\S` inside raw strings (`r"..."`). In a raw string, `\\s` is literal backslash + letter 's', NOT the `\s` whitespace metacharacter. This means **none of the sanitization patterns match anything**. Script tags, inline event handlers, and `javascript:` URLs pass through unmodified.

**Code (validators.py L5-8):**
```python
def sanitize_html(html: str) -> str:
    html = re.sub(r"<script[\\s\\S]*?</script>", "", html, flags=re.IGNORECASE)
    #                        ^^^^ ^^^^
    #   These are literal \s and \S, not regex character classes!
    #   The pattern matches: <script\s\S*?</script>  (literal backslashes)
    #   It does NOT match:   <script  ...  </script> (actual script tags)
```

**Proof — what gets through undetected:**
```html
<script>alert('XSS')</script>           <!-- NOT caught -->
<img onerror="alert('XSS')" src="x">   <!-- NOT caught -->
<a href="javascript:alert('XSS')">      <!-- NOT caught -->
```

**Impact:** Full XSS vulnerability. Any content injected via CMS Rich Text blocks will execute arbitrary JavaScript in browsers.

### BE-SEC-003 — 🟠 HIGH: SSRF Vulnerability in URL Validation

**File:** `backend/app/services/page_service.py`

**Location:** Lines 27-28 (`_validate_url` function)

**Description:**  
URL validation only checks that the string starts with `http://` or `https://`. It does not block internal/private network addresses. An attacker can pass URLs targeting internal services.

**Code (page_service.py L27-28):**
```python
def _validate_url(url: Any, field_name: str) -> None:
    if not isinstance(url, str) or not (url.startswith("https://") or url.startswith("http://")):
        raise ServiceError("VALIDATION_ERROR", f"{field_name} must be a valid URL", 400)
    # No check for localhost, 127.0.0.1, 10.x.x.x, 172.16.x.x, 192.168.x.x
```

**Attack examples that pass validation:**
```
http://127.0.0.1:27017/admin
http://localhost:6379/
http://169.254.169.254/latest/meta-data/  (AWS metadata endpoint)
http://10.0.0.1:8080/internal-api
```

**Impact:** Server-Side Request Forgery. Attacker can probe internal infrastructure, access cloud metadata endpoints, or reach internal services.

### BE-SEC-004 — 🔴 CRITICAL: Database Defaults to Localhost Without Warning in Production

**File:** `backend/app/database.py`

**Location:** Line 12

**Description:**  
If `MONGODB_URI` environment variable is not set, the application silently falls back to `mongodb://localhost:27017`. In a production environment, this could connect to an unintended database if one happens to be running on the same host, or fail silently.

**Code (database.py L12):**
```python
uri = os.getenv("MONGODB_URI", "mongodb://localhost:27017")
# No warning, no production check, no fail-safe
```

**Impact:** In production, if env var is missing, the app may connect to wrong database or expose data.

### BE-SEC-005 — 🟡 MEDIUM: CORS JSON Parsing Crash on Invalid Env Var

**File:** `backend/app/main.py`

**Location:** Lines 35-37

**Description:**  
`json.loads()` is called on the `CORS_ORIGINS` environment variable with no error handling. If the env var contains malformed JSON (e.g., a typo), the entire application crashes during startup.

**Code (main.py L35-37):**
```python
origins = json.loads(
    os.getenv("CORS_ORIGINS", '["http://localhost:5173","http://localhost:3000"]')
)
# If CORS_ORIGINS="not valid json" → startup crash with JSONDecodeError
```

**Impact:** Denial of service via misconfigured environment variable.
